# 05 — Project List and Official Detail Hierarchy

**What to build:** Project records are easier to scan while the map remains primary, and selected-project details prioritize the most useful official information.

**Blocked by:** 01 — Contextual Project Workspace.

**Status:** ready-for-agent

- [ ] The dense list has clearer title, category, status, identifier, hover, and selected-state hierarchy without becoming visually heavy.
- [ ] Official uppercase titles may be presented readably while the original source text remains preserved where appropriate.
- [ ] Contract and project identifiers receive subtle monospace treatment.
- [ ] Details prioritize project name, location, normalized official status, contract amount, contractor, contract ID, important dates, and geometry/source provenance.
- [ ] Secondary metadata remains under `Official details`.
- [ ] Raw source status appears under provenance/source details when it differs from the normalized status, rather than as an equally prominent second status field.
